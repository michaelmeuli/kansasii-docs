## What is shown, and what counts as complete

A batch is one controller job (`runs/<run>/slurm-<job>.out`) that runs Nextflow on one input directory. Three kinds of evidence:

1. **Controller log:** it ends with `Execution status: OK` and the task counts when Nextflow finished. Jobs that stalled, were cancelled or could not open the Nextflow cache have no such end; their batch was submitted again with `-resume`.
2. **Trace files** (`runs/<run>/trace-*.txt`): one row per task with process, sample, status and exit code. The profile repeats a failed task and then ignores it, so `Failed` in a job summary is never 0 and `Execution status: OK` does not prove that every sample has every result. The trace does: a sample counts for a process when one attempt is `COMPLETED` (or `CACHED` on resume).
3. **Result files** (`runs/<run>/assembly/results/<sample>/`): the file each downstream analysis reads exists and is not empty.

A sample is **complete** when all result files the project reads for its kind of run exist (own isolates: also a GTDB species and a CheckM contamination in the summary). Processes the project does not read (Bakta annotation, MetaPhlAn4, pyMLST, QUAST, ... and, for public samples, everything except assembly, GTDB and CheckM) are shown in the process tables but do not enter the verdict.
